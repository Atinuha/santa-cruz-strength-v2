Three defects found, and fixed

All three were invisible on inspection. They surfaced only from measuring the rendered page in a browser at two widths.

WhereWhat was wrongFix
/join, mobile Membership carousel dots were a 22×20 tap target, under the 24×24 minimum, on the page where a mis-tap costs a membership. min-w/min-h set a 24px floor on the button. The 4px dot is unchanged. fixed
Every article The "All articles" link, the only way back out of an article, was 20px tall. py-1 takes it to 28px; -my-1 mb-5 return the 8px, so the header rhythm is identical. fixed
/events Prerendered from no data at all: heading, address, two empty tabs. The one indexable route whose entire value is its list was the one route whose list was never fetched at build time. The prerender now reads /api/events?upcoming=true and the page seeds from that payload, the shape /blog already used. fixed

How the events fix was proved

An empty calendar cannot demonstrate a calendar renderer, so the calendar was filled and then emptied again.

  • A probe event was created through the staff API against the in-memory review database.
  • A full build put PRERENDER PROBE MEET into build/events/index.html. Before the fix it could not have appeared there at all.
  • The probe was deleted and the site rebuilt. The page returned to its honest empty state: "Nothing on the calendar right now", with the tour CTA still in the initial HTML.

An empty calendar is deliberately not a shortfall in the build gate. A quiet month is a true state, not an unseeded database, and the site must not become unbuildable because nothing is booked.
